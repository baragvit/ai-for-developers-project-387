# Контракт API на TypeSpec — единственный источник правды

HTTP-контракт описан в `api-contract/main.tsp`; из него генерируются `openapi.yaml`, клиентский SDK фронтенда (`openapi-typescript` + `openapi-fetch`) и типы DTO бэкенда. Поведение меняется сначала в контракте, затем на обеих сторонах. Генератора серверных маршрутов и валидации для Fastify нет, поэтому схемы zod в `backend/src/api/validation.ts` повторяют ограничения контракта вручную, а совпадение проверяют API-тесты; CI падает, если сгенерированные файлы расходятся с контрактом.

## Considered Options

- Код первым, OpenAPI из кода бэкенда: фронтенд не смог бы развиваться на моке до появления бэкенда.
- Ручной клиент на `fetch`: типы расходились бы с сервером молча.
